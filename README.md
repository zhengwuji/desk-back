# 桌面布局管家 (Desktop Layout Keeper)

> 记住你桌面图标的排列，一键恢复；不听话的时候还能把它**锁住**。

[![编译并发布](https://github.com/zhengwuji/desk-back/actions/workflows/build-release.yml/badge.svg)](https://github.com/zhengwuji/desk-back/actions/workflows/build-release.yml)
[![最新版本](https://img.shields.io/github/v/release/zhengwuji/desk-back?label=%E6%9C%80%E6%96%B0%E7%89%88%E6%9C%AC&color=blue)](https://github.com/zhengwuji/desk-back/releases/latest)
[![下载量](https://img.shields.io/github/downloads/zhengwuji/desk-back/total?label=%E4%B8%8B%E8%BD%BD)](https://github.com/zhengwuji/desk-back/releases)

Windows 上摆得好好的桌面图标，装个软件、插个 U 盘、分辨率一变就被系统重排得乱七八糟。
这个工具把当前布局存成一套命名快照，之后点一下「恢复」就精确回到原样；再点一下「锁定」，
以后图标被拖走还会自动拉回来。

- **免安装单文件**，不写注册表、不加开机自启、不联网
- 只读写桌面图标的**位置**，不碰任何文件内容
- 布局数据存在 `%APPDATA%\DesktopLayoutKeeper\layouts.json`，纯文本可读可备份

## 下载 & 安装

到 **[Releases](https://github.com/zhengwuji/desk-back/releases/latest)** 下载最新的
`DesktopLayoutKeeper_v?.exe`（约 12 MB），丢到任意一个固定目录就行 —— 不用安装，卸载就是删掉它。
下载后**可以随便改名**（比如改成 `桌面布局管家.exe`），不影响使用 ——
发布包用英文名是因为 Windows 上 `gh` 上传中文文件名时会把中文整段丢掉
（`桌面布局管家_v1.exe` 会被传成 `_v1.exe`），所以发布统一走 ASCII。

> 想自己编译、或者不放心别人打包的 exe：见 [自己编译](#自己编译)。
> 每个 Release 里都附了 SHA256，可以对一下。

**没有代码签名**，所以 SmartScreen 可能会弹"Windows 已保护你的电脑"。
点「更多信息」→「仍要运行」即可。这是所有未签名的个人小工具都会遇到的情况。

## 怎么使用

1. **右键 exe →「以管理员身份运行」**（推荐）。
   读改桌面图标的位置要跨进程操作 `explorer.exe`，权限不够时可能读到失败。
   忘了也没关系，程序会在顶部用橙色横幅提醒你，并给一个「以管理员身份重启」按钮。
2. 先把桌面图标摆成你喜欢的样子。
3. 点右侧 **「保存当前桌面布局」**，起个名字（默认会叫"我的桌面"）。
   想留个干净的初始版本，就先保存一份再开始折腾。
4. 以后桌面乱了，选中那套布局，点 **「恢复选中布局」**（在列表里**双击**也一样）。
5. 想让布局谁都动不了，点 **「锁定选中布局」**。之后每隔 2 秒检查一次，
   发现图标被拖走就立刻拉回原位；再点一次即可解锁。

### 界面上每个按钮干什么

| 按钮 | 作用 |
| --- | --- |
| 保存当前桌面布局 | 把当前每个图标的**名字 + 坐标**存成一套命名快照 |
| 恢复选中布局 | 一键还原到选中那套（列表里双击同一效果） |
| 锁定选中布局 | 后台盯着，一旦漂移就拉回原位；按钮会变成「解除锁定」 |
| 重命名选中布局 | 改名字 |
| 删除选中布局 | 删掉这套快照（不可撤销） |
| 把图标对齐到网格 | 手动整理一次，让图标排齐（会自动关掉「自动排列」） |
| 立即刷新桌面状态 | 重新读一遍桌面，刷新下面的图标数/开关状态 |
| 导入布局… / 导出全部… | 和别人交换布局，或者备份成 JSON |
| 打开数据目录 | 直接打开 `layouts.json` 所在文件夹 |

### 顶部那条彩色横幅

| 颜色 | 含义 | 能做什么 |
| --- | --- | --- |
| 🟢 绿色 | 当前以**管理员**身份运行 | 桌面读写、锁定全部可用，右边按钮显示「已提权」 |
| 🟠 橙色 | 当前是**普通用户** | 明确告知可能读写失败（错误 5），右边给一个「以管理员身份重启」按钮，点一下用 UAC 重新拉起自己 |

选项里勾上 **「总是以管理员身份运行」**，下次启动时会主动问你要不要提权。

### 选项区的三个开关

- **恢复前自动备份当前布局** —— 恢复之前先偷偷存一份"恢复前"，手滑了还能退回去。
- **恢复时关闭「自动排列图标」** —— 默认勾上，**建议保持**。
  Windows 的「自动排列图标」开着时会自己按列重排，你手写的坐标随时可能被它覆盖，
  所以恢复和锁定都要求它是关的。代价是它会改你桌面右键菜单里的这个开关
  （只改这一个，不动别的设置）。
- **名称对不上时按顺序兜底** —— 有个别图标改名了、或者新装了软件多出图标时，
  按顺序硬对一遍，尽量还原大部分位置。

## 常见问题

**桌面图标数量或名字会变，能还原吗？**
能。优先按**名字**匹配，所以中间插了几个新图标、删了几个旧图标都不影响其他图标归位。
名字实在对不上时，如果勾了「按顺序兜底」就按顺序硬对。

**会不会把我桌面的「自动排列图标」打开？**
不会，只在恢复/锁定时按你的选项把它关掉；解锁后不改回来，因为开了它布局就守不住。
想恢复成系统自动排列，右键桌面 →「查看」→ 勾上「自动排列图标」即可。

**为什么普通用户模式偶尔读不到桌面？**
如果 `explorer.exe` 是管理员身份启动的（完整性级别更高），普通权限进程打不开它的窗口句柄，
状态栏会显示 `读取失败（OpenProcess 失败，错误 5）`。这不是崩溃，是在提示你去点
「以管理员身份重启」。

**它会不会偷偷联网 / 上传我的东西？**
不会。整个程序只用了 Python 标准库（`ctypes` 调 Win32 API + `tkinter` 画界面），
唯一写盘的地方是 `%APPDATA%\DesktopLayoutKeeper\`。源码就在本仓库，可以自己审。

**支持多显示器吗？**
布局里存了保存时的显示器信息；能分别记住每个桌面视图（`Progman` 和 `WorkerW`）的布局。
但我手上只有单显示器环境，多屏没做过真机验证 —— 见 [已验证 / 未验证](#已验证--未验证)。

## 自己编译

需要 Python 3.8+（推荐 3.11 以上）：

```bat
python -m pip install pyinstaller
python build.py                     :: 编译号 +1 并编译（最常用）
python build.py -m "加了开机自启"    :: 顺带记一条备注，写进 VERSION
python build.py --no-bump           :: 不 +1，原地重编译（改代码反复试的时候用）
python build.py --clean             :: 先清 build\ 和 dist\ 再编译
python build.py --keep-versions 5   :: 只留最近 5 个历史 exe
python build.py --ascii-name        :: 产物叫 DesktopLayoutKeeper_vN.exe（发布用）
```

产物落在 `dist\桌面布局管家_vN.exe`，同时覆盖一份到根目录 `桌面布局管家.exe`；
加了 `--ascii-name` 就是 `dist\DesktopLayoutKeeper_vN.exe`（发布用）。

不装 PyInstaller 也能跑：`python src\desktop_layout_keeper.py`，或者双击根目录的 `启动.bat`。

编译完想确认版本号真的烧进去了：

```bat
"桌面布局管家.exe" --version
:: 桌面布局管家 v3（内核 1.2.0，打包版）
```

也可以右键 exe →「属性」→「详细信息」，看「产品版本」。

适合做计划任务，比如登录时自动备份一份：`桌面布局管家.exe --cli-save 开机备份 --overwrite`。

运行的（没有父控制台），输出会落到 `%APPDATA%\DesktopLayoutKeeper\cli-output.txt`。

## 它是怎么实现的（两个坑）

桌面图标不是一个普通窗口：它属于 `explorer.exe` 的
`Progman / WorkerW → SHELLDLL_DefView → SysListView32`，我们的进程只能隔着进程边界
用 `ReadProcessMemory` / `WriteProcessMemory` 去读写，所以代码里全是这些细节。

**坑 1 —— 读回来的坐标和写进去的不一样**

写坐标用的是 `LVM_SETITEMPOSITION`。写完必须**读回来核对**，否则可能出现"调用成功但
图标没动"。本工具每写一批就重读一遍，结果里直接给出 `restored / verified / mismatch`
三个数字，错位的图标名字会全部列出来。

**坑 2 ——「对齐到网格」会换掉坐标的坐标系**

这是最阴的一个。同一个格子，「对齐到网格」**开着**时读出来是 `(0,5)` 这样的**格点坐标**，
**关掉**时是 `(13,2)` 这样的**像素坐标**。也就是说：

- 保存时开着、恢复时关着 → 写进去的像素值会被解释错，图标飞到离谱的位置
- 反过来也一样

而且这个开关是在**写**的那一刻被解释的，单纯切开关再读、坐标不会跟着换算。

所以本工具的做法是：

1. 保存时记下当时的开关状态；
2. 恢复前先把开关拨回同一个状态，再写坐标；
3. 比对时**自校准**：让每个图标各投一票（当前坐标 − 目标坐标），
   票数集中到同一个值（≥60% 且偏移在 ±64px 内）就认定这是"坐标系差异"，
   票分散就认定是图标真的被拖走了。

这样既能**逐个精确还原**（实测 62/62 全部对上），也不会误判成"你移动过图标"，
更不会去改你桌面右键菜单里的其它设置。

## 版本号是怎么显示的

分两层，避免"改了代码忘了改版本号"这种糊涂账：

| 层 | 例子 | 在哪看 | 谁负责 |
| --- | --- | --- | --- |
| **编译号** | `v1` `v2` `v3` … | 窗口标题、任务栏、`--version`、exe 属性→详细信息、Release 页面 | 自动递增 |
| **内核版本** | `1.2.0` | `VERSION` 里的 `kernel`，源码里的 `APP_VERSION` | 手改（大改动时） |

窗口标题长这样：

```
桌面布局管家  v3
```

从源码跑（没编译）时标题显示 `v-dev`，一眼看出"这不是正式版"。

**编译号有两条轨道**，都单调递增，不会重号也不会互相覆盖：

- **本地**：`python build.py` 读 `VERSION` → 编号 +1 → 写回 `VERSION` 并记进 `history`。
  版本号只在 `VERSION` 这一个文件里改。
- **云端**：GitHub Actions 用**本次运行序号**当编译号
  （`build.py --build-number N`，**不读也不写** `VERSION`）。
  这样做是为了避免云端和本地各自涨号、互相覆盖、还要处理推送分叉。
  Release 页面上的 v1、v2、v3 就是云端这条轨道。

## 根目录规则

这个目录**只放"入口"和"规则"**，具体实现全部丢进子目录，一眼能看出哪个是给人双击的：

```
桌面布局/
├─ 桌面布局管家.exe        ← 最新版 exe（编译产物，不进仓库，从 Releases 下载）
├─ 启动.bat                ← 源码方式启动（优先用 exe，没有 exe 才退回源码）
├─ 以管理员身份启动.bat    ← 提权启动（UAC）
├─ README.md               ← 这份说明 + 规则
├─ VERSION                 ← 本地版本号唯一来源：vN 编号、备注、历史
├─ build.py                ← 一键编译：版本 +1、烧版本号进 exe、生成 vN.exe
├─ src/                    ← 源码，只放 .py
│   └─ desktop_layout_keeper.py
├─ assets/                 ← 图标和图标生成器
│   ├─ make_icon.py        ← 纯标准库画 ICO（不依赖 Pillow / ImageMagick）
│   ├─ app.ico             ← 编译时用的图标（10 个尺寸：16…256）
│   └─ app_preview.png
├─ .github/workflows/      ← CI：推送即编译并发布 Release
├─ dist/                   ← 历史版本 exe（编译产物，不进仓库）
├─ build/                  ← 编译中间产物，整目录可随时删（不进仓库）
└─ _dev/                   ← 开发期自测脚本，不是交付物，可整目录删
```

规矩就三条：

1. **根目录不放实现代码。** 新代码写进 `src/`，新素材写进 `assets/`，新脚本进 `_dev/`。
2. **版本号只在 `VERSION` 里改。** 不许在源码里手写 v3、v7 之类的编译号——
   编译号由 `build.py` 从 `VERSION` 读出 +1 再写回，永远单调递增，不可能对不上。
3. **产物只往 `dist/` 和根目录最新 exe 写。** 其它文件都别在根目录生成。

两个 `.bat` 是**纯 ASCII** 的，一个中文字符都没有：不写死中文 exe 名（用 `%~dp0*.exe`
通配），提权时用环境变量把路径传给 PowerShell。这样不管 cmd 的控制台代码页是 936 还是
65001，都不会出现"双击没反应"的乱码问题。改启动参数就重跑 `python _dev\_write_launchers.py`。

## 已验证 / 未验证

真机回归（Windows 11 26200，2560x1440，单显示器，62 个桌面图标）实测通过：

- 保存 → 打散 → 恢复：`restored 62 / verified 62 / mismatch []`
- 锁定：人为拖走一个图标后，下一轮被自动拉回原位，第二轮漂移数 0（收敛）
- 端到端走真实的 `layouts.json` + 命令行恢复：同样 62/62
- 打包版 exe 端到端恢复：`restored 62 / verified 62 / mismatch []`，复核漂移 0 处
- 图标：从 exe 里取出系统实际使用的 32×32 图标，确认就是画的那套（网格 + 锁）
- 版本：`--version` 输出正常；PE 版本资源、图标资源（10 个尺寸）、清单都完整
- GUI：普通用户 / 管理员两种模式都截图确认过，按钮无裁切
- 提权调用链：用假 shell32 记录 `ShellExecuteW` 参数，确认 `verb=runas`、
  目标与参数正确，UAC 取消（rc≤32）时正确判成失败

**未覆盖**：多显示器、桌面文件名重复、超过一屏需滚动的图标。
这些场景代码里都有兜底（按名字优先匹配、对不上时可按顺序兜），但没有真机样本。

**未验证**：真实 UAC 确认框的人工点击（无人值守环境会让安全桌面卡住），
提权调用链是用假 shell32 验的参数与返回值判定。

## 开发脚本

`_dev/` 里是写这个工具时用的自测脚本，不影响正常使用（它们都自带 `sys.path` 补丁指向
`src/`，可在任意目录执行）：

- `_selftest.py` —— 端到端回归（会真的动你的图标，最后会还原并复位开关）
- `_diag.py` —— 打坐标 / 开关 / 网格间距的诊断
- `_e2e_store.py` —— 走真实 `layouts.json` 的端到端
- `_restore_desktop_state.py` —— 把桌面的「自动排列 / 对齐到网格」复位成开
- `_write_launchers.py` —— 重新生成根目录那两个 .bat
- `_shot.py` —— 抓窗口截图（`--attach 桌面布局管家.exe` 可抓已在运行的实例）
- `_check_elevation.py` —— 假 shell32 验证提权调用链，不弹 UAC

> 跑自测前记得先把桌面布局存一份。
